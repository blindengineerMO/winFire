# WinFire Internet extension enterprise deployment

The Internet extension is telemetry-only until an administrator enrolls a browser device and
publishes a policy. The public `/tools` page contains the signed development packages and links to
store listings when they are available. A package never contains a tenant URL, enrollment code, or
credential. Enrollment is completed in the extension options page with a short-lived, single-use
code generated by WinFire.

## Deployment model

1. Create an Internet enrollment for a node or node group in **Visibility → Internet**.
2. If identity filtering is required, bind the enrollment to an enabled WinFire or AD-backed
   operator. Without that explicit binding, events remain device-scoped and appear as **Unmapped
   user**.
3. Deploy the signed extension package through the browser management system or provide the
   `/tools` link to users. The package must be signed and hosted over HTTPS.
4. The user enters the one-time enrollment code and accepts the displayed collection and privacy
   disclosure. WinFire records the enrollment and the device credential can be revoked from
   Administration.
5. Stage and publish Internet policy changes, then use **Sync policies** to deliver them. A
   disconnected extension keeps its last confirmed signed rules; it never treats a staged policy
   as active.

## Chrome and Chromium Edge

Use the browser's managed `ExtensionSettings` policy in Group Policy, Intune, or another endpoint
management system. Replace the placeholder extension ID and update URL with the values from the
signed release manifest. Force-installing a package is appropriate only after the privacy notice,
collection level, and enrollment ownership have been approved by the organization.

```json
{
  "EXTENSION_ID": {
    "installation_mode": "force_installed",
    "update_url": "https://clients2.google.com/service/update2/crx",
    "runtime_blocked_hosts": ["*://*/*"],
    "runtime_allowed_hosts": ["https://winfire.example.com/*"]
  }
}
```

`runtime_allowed_hosts` is only an example for the WinFire control-plane origin used by the
extension. Do not add broad administrative origins to a browser policy. If the organization uses a
private CRX distribution, use its signed update URL and publish the matching policy through the
Chrome or Edge management channel. Edge deployments must follow Microsoft's managed-extension
requirements; a self-hosted Edge package is intended for domain-managed devices, not universal
Entra-only distribution.

## Firefox Enterprise

Firefox accepts an enterprise `policies.json` file. Use the signed release URL and the extension's
update manifest; do not embed an enrollment code in the policy file.

```json
{
  "policies": {
    "ExtensionSettings": {
      "EXTENSION_ID": {
        "installation_mode": "force_installed",
        "install_url": "https://winfire.example.com/tools/winfire-internet-firefox.xpi",
        "updates": "https://winfire.example.com/tools/winfire-internet-firefox-updates.json"
      }
    }
  }
}
```

The Firefox package declares its optional host permissions and private-window behavior in the
manifest. Keep private-window access disabled unless the organization's approved collection policy
requires it. WinFire's extension must continue to exclude private browsing by default.

## Native identity helper boundary

AD SID/session correlation is an optional, separately installed native helper. The extension and
control plane must continue to work when it is absent or offline. A future helper may use a
browser-managed native messaging host, but it must be installed by an administrator, use an
allowlisted extension ID, authenticate its local IPC requests, and return only a short-lived
device/session binding. It must not return page contents, cookies, credentials, or form data. The
helper protocol and live browser identity validation remain open plan work.

## Rollout and rollback

- Begin with a telemetry-only node group and verify event redaction, private-window exclusion, and
  user binding before enabling blocking policies.
- Keep the extension minimum-version setting aligned with the signed package and revoke a device
  credential before removing a browser from management.
- Publish an emergency rollback Internet policy before enabling a block rule. **Sync policies** is
  the deliberate deployment point for normal changes.
- Exported Internet events follow the same RBAC and redaction rules as the Internet view; no
  deployment policy grants access to page content or credentials.
